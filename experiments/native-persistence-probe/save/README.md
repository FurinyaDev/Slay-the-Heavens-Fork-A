## 编辑器操作清单

1. 使用独立实验副本、新测试用户/无试验数据的用户。建「超限模式」关卡，玩家最少和最多均为 `1`。记录区服、客户端和编辑器版本、账号权限和实验候选身份。系统菜单查看奇匠权限并确认「高级数据管理」和「局内存档管理」可进入。所有配置改在实验副本。正式发布操作由 Owner 执行。 [界面入口](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhn4bsi5lb58) · [模式](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh29wpicgvh0)
2. 系统菜单 →「高级数据管理」→「局内存档结构体」→「创建结构体」。按 [save-probe.json](save-probe.json) 创建 `STH_EXP_SAVE_ROW`，依序添加 `schema` 整数 `0`、`token` 整数 `0`、`flag` 布尔值 `false`、`label` 字符串空串、`samples` 整数列表 `[0,0]`。为 `samples` 添加两个元素定义内层长度 `2`，点击「全部应用」。从界面记录自动分配的配置 ID。 [结构体](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh3fmi0t99ns) · [配置截图](https://act-webstatic.mihoyo.com/ugc-tutorial/knowledge/cn/zh-cn/mhzcw29qjjma/531af301-8a3c-4b86-ba87-55f72feea1ff.png)
3. 系统菜单 →「局内存档管理」→「创建局内存档模板」→ `STH_EXP_SAVE_V1` →「添加局内存档数据」。选择 `STH_EXP_SAVE_ROW`、长度 `1`，打开「启用局内存档」。截图记录行和总数据量。打开玩家实体 →「自定义变量」→「局内存档变量」，核对真实变量名、类型「结构体列表」、长度 `1`。本说明按 `STH_EXP_SAVE_ROW` 指代它，实际接线以界面读回为准。若查无变量，核对启用与测试模式，不能把查询返回的类型默认值当成空档。 [局内存档](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhzcw29qjjma) · [玩家变量截图](https://act-webstatic.mihoyo.com/ugc-tutorial/knowledge/cn/zh-cn/mhzcw29qjjma/8d4f2e5a-0cfc-4f38-b636-c6c770c31983.png) · [查询节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhwbqlrw655q)
4. 在信号管理器按配置顺序定义 `STH_EXP_SAVE_REQUEST` 和 `STH_EXP_SAVE_OBSERVATION`。创建并挂载玩家服务器节点图 `STH_EXP_SAVE_PLAYER`，加一个整数节点图变量 `sessionToken=0`。`实体创建时` 以事件源玩家实体为目标，立即读取局内存档变量，输出 `create`、行数和首行字段。先检查列表长度才用 `获取列表对应值` 读取序号 `0`，再 `拆分结构体`。首行不存在时记录 `rows=0`。这条支路没有写入或假数据注入。 [事件节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhn7ko01v3yw) · [运算节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhnd4l069tk0)
5. 图的 `监听信号` 选择 `STH_EXP_SAVE_REQUEST`。检查信号来自唯一实验玩家并以该玩家实体为目标。首次试玩把 `事件源实体` 和 `信号来源实体` 与玩家对照，记录可用的发件人字段。`op=0, requestToken=0` 只读。写动作按 JSON 的 `(op,token)` 白名单接收。用 `拼装结构体` 生成完整一行 `schema=1, token=requestToken, flag=true, label=EXP-é-千, samples=[11,22]`。`op=2` 附加第三个样本 `33`。`op=3` 附加第二行 `token=499`，其余字段与首行相同。`拼装列表` 后只调用一次 `设置自定义变量`，随后 `获取自定义变量`。读回与预定首行和长度一致才把节点图变量 `sessionToken` 写成 `requestToken`，打印请求值与实读值。不符、没有事件或报错保留原始记录。针对断网用例记录服务端是否收到了请求。 [信号](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhlaj0r9bldi) · [执行节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhw66orrrfkm)
6. 每次处理后用 `发送客户端脚本信号` 给同一玩家发送 `STH_EXP_SAVE_OBSERVATION`，字段按配置填写。空档没有首行时仅在回复中用 `schema/token=0, flag=false, label="", samples=[]`，以 `rowCount=0` 标明空档。如果目标版本的信号节点不能携带这些参数，记录信号限制，使用原生节点日志从 `create`、`readback` 验证存档，并保留 Lua 通道未验；也可在节点图以原生控件触发同一个实验分支并记录原生日志。发布运行若无法获取日志或界面数据，则该用例保留待测。 [执行节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhw66orrrfkm) · [节点图日志](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhu951iz7wz8)
7. 把 [save-probe.lua](save-probe.lua) 挂到独立客户端控件容器。在容器下放一个名为 `status` 的文本视窗和 JSON `buttons` 中同名的八个光标检测区域控件，配可见按钮文字。`read` 只读，其他按钮会写入带唯一值的实验样本。先看 `ready`，点 `read`，再跑用例。脚本只发送探针请求并显示读回。启用本轮原生日志与客户端脚本日志，图、脚本、变量和候选身份都须读回核对。 [客户端控件 API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4) · [官方试玩](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhie54ik9ovg)

自动化可完成冻结样品 SHA、源码检查、候选审计及官方客户端侧录。连接仓库已配置的 Windows MCP 后，先读 `miliastra://workflow` 和 `miliastra://platform-rules`，设置 `MILIASTRA_ALLOW_LIVE_WRITE=0`，只写存档副本。`scene_add_graph` 返回的真实图 ID 才能用于已有图编译/写入链。试玩用 `clientScriptLog: true`，核对新一轮日志和截图。创建存档模板、能力解锁、授权发布、实际断网恢复/杀进程需要目前的编辑器/实机交接。操作权限和窗口按仓库 [工具链](../../docs/TOOLCHAIN.md) 执行。

## 实机实验矩阵

先用试玩核对字段、钩子、信号和失败行为。`试玩临时数据管理` 的预填仅用作分立的旧数据/默认值读入对照。持久化用例须在实际允许跨进场保存的独立实验关卡运行，首次 `read`、退出前读回和新进场读回全程取证，禁用预填。把同身份/版本保存的实验产物依次用于以下测试。每个故障用例从一轮事先正常退出并且新进场已读回的 `101` 开始。

| 用例 | 操作和判读 |
| --- | --- |
| 初始值与正常退出 | 新测试玩家进场即记录 `create`。点 `baseline` 后保存 `readback`（`saved=101`, `rows=1`, `session=101`, `flag=true`, `label=EXP-é-千`, `samples=[11,22]`）。走官方退出并回到外部页面，新进场先取 `create` 再点 `read`。预期恢复同值，`sessionToken` 默认 `0`。条件允许时在另一设备用同一账号、同区服重进，补排除客户端缓存的对照。 |
| 短暂断网，同房间恢复 | 写 `212` 后等明确的服务器变量读回，再断网。连回时先看平台是否回原房间，从实例标识、`create` 事件和 `sessionToken` 取证。若为同实例，先读 `212` 再明确退关并开新实例测持久化；只有同房间读回时记录为同实例结果。 |
| 断网后新进场 | 两次独立运行。一次先隔离网络再点击 `net_before`（`211`），一次写 `212` 并收到读回再断网；均等待平台结束/离开本次连接，恢复网络并开新实例。分别记录客户端发送、服务端收到、局内读回、是否然后正常退关、最终读回 `101`、`211`、`212` 或其他。覆盖短断与超时退房。 |
| 强杀后新进场 | 两次独立运行。一次点击 `kill_before`（`311`）后在读回前终止实验客户端进程，按日志确认该时间点并重跑无法命中的尝试；一次写 `312` 收到读回后直接终止。均记录 UTC 时间，不走退出/结算流程。重启并证明确实新进场再读，区分基线 `101` 的持久性与最新 `311/312` 的提交状态。 |
| 列表超长 | `inner` 局内读回 `[11,22,33]`，正常退出重进按官方预期读 `[11,22]`。`outer` 局内 `rows=2` 并在日志记录第二行 `499`，正常退出重进按官方预期 `rows=1`、首行 `402`。若编辑器、节点写入、信号传输先拦截或截断，分别记录发生环节。类型负对照在副本验证错误泛型/不支持成员是否被编辑器拒绝。 |
| 容量计量 | 另建只用于容量的副本，从单整数、外层长度 `1` 起截图总数/行数据量。每轮只改一个因素。轮换每种支持的标量和列表，记录一、两个槽位的差额，调整外层长度 `1→2→3`，更改同一字符串字段的空、ASCII `a`、中文 `千`、多字节值的默认长度并比较读数。GUID、阵营、元件 ID、配置 ID 用当前副本真实有效的值并留截图。验证名称为「单个局内存档结构体数量」的 `100` 对应实际配置对象及结构体长度 `200` 的编辑限制。增减合法结构条目找到最大可接受点和首个超限点，记录 `/10000` 原样数值、失败提示和准确阶段。记录不同字符编码长度作比较，只有面板能证明字段成本，若无法正好凑 `10000` 则给出最近上下界。 |
| 增量兼容 | 保留 V1 已读回的 `101`，在独立实验关卡同一发布身份上新增 `added=707` 和第二个存档结构条目 `STH_EXP_SAVE_EXTRA`（其 `addedDefault=708`、外层长 `1`）。升级前保存模板对比证据，保持既有模板与字段身份，更新探针日志显示新字段。V2 首次进入核对 `101` 全量与两个默认值；若新增条目在空列表，以实际数据形态记录并核对默认值可见条件。负对照换字段类型或缩小长度只在可丢弃实验副本看对比失败、发布拦截或实际重置。 |

每例记录候选 SHA 与 `.gil` hash、关卡/房间身份、区服、PC/手机和版本、玩家账号脱敏别名、试验及各事件 UTC 时间、前后完整行、当前/新实例证据、截图和服务端/客户端日志。持久化确认只授予经过独立新进场读回匹配记录的那一笔。局内 ACK 依赖实机能力，`SendSignal` 本身、脚本打印和回调回执均不承诺落盘。

## 后续接入契约

| 边界 | 契约 |
| --- | --- |
| 数据所有权 | 当前单人 Lua 业务拥有 Run 和事务。仅从成功提交的稳定边界取候选 checkpoint，通过轻量适配将版本、Run 标识、单调修订和已有快照/随机流数据交给服务器节点图。该图验证与替换属于目标玩家的存档变量，保留每个玩家的数据边界。合作权威归既有 ADR。UI 与动画由业务状态投影。 [ADR 0001](../../docs/adr/0001-coop-and-high-fidelity-primitives.md) |
| 表达与提交 | 字段类型、编码与最大长度由平台实测定稿。发送前按 Schema 上限检验，服务端再检验发件人、版本、修订、类型及长度。无法编码或超限时拒绝整个 checkpoint，保留上一条完整有效记录。单次替换一份一致的存档变量，重复发送相同修订且载荷一致时保持幂等。过期、同修订载荷冲突、错误玩家和无法确认的读回留证据，避免重试覆盖较新进度。 |
| 两种确认 | 适配层可表述「请求已发」「服务端变量读回吻合」「新进场读回吻合」三种观测。超时等同未知，重新读回后才决定是否重发。若官方无可证的持久化回执，服端局内确认不能用于向玩家承诺已存档或可关闭客户端。 |
| 恢复 | 玩家创建后先取原生载入结果，再决定恢复入口。验证完整性和版本，交给已有模块恢复器与可信上下文。`abyss_snapshot.capture` 用于内存事务回滚，`Run.restoreEncounters` 仅在现有 Run 的合规边界恢复遭遇子状态。持久恢复需要覆盖完整 Run 标识、阶段、难度与进度、角色资源、卡牌 UID/升级、遗物/药水/次数、随机流及所批准的稳定边界。未知版本、坏档、截断、能力不可用均明确失败，保留现场和已读有效数据。 |
| 版本与验证 | 升级保留 Schema 身份，按增量变更，验证历史数据和下一次重进。使用既有事务、地图、随机流及快照的回归测试，再按同一候选复测低端设备和负载证据。上线范围和最低保证由同实例、正常退出、断线、强杀的真实证据确定。 [平台负载](../../docs/PLATFORM_LOAD.md) |
