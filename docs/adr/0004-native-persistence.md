# ADR 0004 千星奇域原生成就与局内存档的接入边界

日期 2026-11-26。状态 **待实机验证**。适用于 TASK-45、TASK-53 的后续业务版本。EXP 的测量步骤和当前结果见 [平台探针](../../experiments/native-persistence-probe/README.md)。

## 权威与边界

- Lua 继续持有单机 Run 的现有业务状态、事务顺序、统计、快照和随机流。只从已提交业务边界取证。原生节点图以平台识别的玩家作为外围数据读写主体，持有成就进度和玩家存档的原生读写权。Lua 与 UI 只显示确认等级允许的结果。
- 复用已存在的客户端到服务器信号，并实测服务器定向回复给对应玩家。原生图先核验平台提供的发件人、请求约束及重复键的作用域。现有全局结算图仅证明项目已有信号通路，不授权将请求载荷里的身份用于成就及存档。可信身份无法取得时，记录实际出参和限制并保留阻塞。
- 原生读写集中在轻量 Adapter。调用者复用现有提交、快照与恢复入口。持久发布前核对只写同一玩家、同一业务提交以稳定操作键重试、旧数据兼容、关卡重建取回正确版本以及关卡和角色切换边界。

## 拟验证接口

以下是接入语义，平台信号参数与节点以实机证据定稿。读写将生成相关 ID，附能力、操作、协议版本与原生结果。客户端到服务端必须能区分新请求、原请求重试和同键异值，兼容性未知时保留失败状态。原生 id、字段 ID、确切存档大小及计量口径、回复时序均由本轮编辑器或验证记录给出。

| 操作 | 请求 | 原生结果和确认条件 |
| --- | --- | --- |
| 查询成就 | 已核验的人和成就序号 | 平台的完成状态。只有原生提供且实测的进度字段可以读取 |
| 更新成就 | 稳定业务提交键、成就序号及已提交统计或命令 | 原生图更新并读回支持的状态。重复请求必须用实测语义去重，尤其是累加。永久完成单独经重进或可证明的持久确认核验 |
| 读取存档 | 对应的玩家、模板及支持版本 | 返回有效数据、确定无存档、版本过新或读取失败。读取先校验版本和完整性，正常挂载仍走现有恢复入口 |
| 写入存档 | 稳定提交键、预期修订、Schema 版本及完备快照 | 分开记录节点受理、同一实例写入读回、持久化确认。持久确认依据原生确认的合同或同身份新实例读回证据 |

状态词为实验契约。`accepted` 表示节点图已收到，`applied` 表示目标数据在该实例中读回一致，`durable` 只用于具有真实持久性证据的值。`unsupported`、`permission_denied`、`invalid`、`conflict`、`incompatible`、`capacity` 和 `native_error` 对应已识别的拒绝或不满足条件。`timeout` 或失联后结果为 `unknown`，应先读回对账或用同一操作键重试。保留原生原因，读写结果未知时保留最近已证实的状态；重试必须依赖实测能支撑的幂等边界。

## 放行

官方指南公开双向信号及退出存档时机。真实平台需证明创作者能使用两项能力、应用满足批准设计、玩家归属与定向回复正确，以及正常退出、断网和杀进程后承诺的状态可以恢复。若存在平台硬限制，保留最小证据并提请决策。成就 ID、存档精确容量算法与服务器持久化 ACK 当前均待验证。 [客户端脚本](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww) · [成就](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh65jrr2yj3i) · [局内存档](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhzcw29qjjma)
