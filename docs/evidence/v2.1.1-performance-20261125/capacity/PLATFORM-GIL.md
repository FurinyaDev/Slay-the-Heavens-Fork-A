## 官方机制

- 编辑器的静态全局页汇总各区域，计算与内存分别有推荐阈值。区域详情按实体、场景及朝向解释，推荐阈值告警意味着风险。指南明确规定关卡存档超限禁止上传。静态通过无法评估运行时脚本创生的负载。 [官方《负载计算功能》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mho2hirgodxi)
- 在「关卡设置 → 基础配置 → 负载设置」可配置期望最低档位。提高档位同步提高编辑时的告警阈值，作品详情展示结合配置和实际编辑情况的最终负载需求，玩家入场前可收到提示。官方指南只说明提示和告警，玩家此次无法进入的触发条件及错误码仍待取得。 [官方《负载计算功能》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mho2hirgodxi)
- 千星沙箱「窗口 → 负载检测」开启后正常试玩、退出，报告自动导入。分别读取客户端计算、客户端内存、服务器处理器、服务器内存。检测本身增加负载，时间实验需补同设备、同场景的检测关闭对照。指南说明客户端上限按普通电脑配置，客户端内存“其他”受最大人数影响，服务端按配置最小人数分配。有效对照需保留人数设置和负载档位。 [官方《负载计算功能》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mho2hirgodxi) · [仓库负载合同](https://github.com/FurinyaWorks/Slay-the-Heavens/blob/55d6396c/docs/PLATFORM_LOAD.md)
- 响应链路按 T0 点击进入、T1 首个 Lua 标记、T2 初始化完成、T3 菜单命中成功并产生状态反馈打点。T0→T1 包含平台下载或缓存、宿主资源准备与 Lua 调度，数据缺失保留 `UNVERIFIED`。T1→T3 在同次会话对照模块初始化、UI 绑定、首屏到交互的本地开销。离线启动只可验证 T1 之后有记录的功能路径。iPhone 14 Pro、受影响移动设备要同时记录客户端版本、画质、网络、热状态、冷暖缓存及平台提示，才能解释差异。

## 历史证据与处置

- PR #808 的完整含音频 GIL 从 26,076,818 B 降到 25,147,821 B，减少 928,997 B。其紧凑怪物路径在 `require` 解出 42 资产和 3,385 图元。这是一项有明确计算代价的体积优化；本轮同数据三组实测由启动分析记录。去除未被读取的旧战斗画像不引入这道解码。 [PR #808](https://github.com/FurinyaWorks/Slay-the-Heavens/pull/808)
- PR #890 的同底图有声 GIL 从 24,926,460 B 降到 23,718,462 B。原生 UI 分段少 1,027,668 B，对照读回定位到 1,305 个不可见边框子控件。Lua 段少 180,330 B，正式入口不可达的四角色未来卡牌数据用报错桩保留入口约束。该实验确认序列化收益，真实宿主的启动与内存效应没有同设备配对数据。 [PR #890](https://github.com/FurinyaWorks/Slay-the-Heavens/pull/890)
- 更早的多项压紧实验显示不同表示的成本各异。既有 121 组交错 Lua 5.3.6 样本中，六模块编译加执行 p50 从 43.634 到 36.784 ms，保留堆从 7,234.09 到 6,551.29 KiB。另一项原生卡面模板共享虽在实际 GIL 省 6,582,087 B，实际模拟宿主 `GetChild` 无法进入引用因此未采用。保留按需解码的首战验收，先测隐藏面板实际驻留与原生创建，再考虑进一步改动布局。 [既有容量对照与负例](https://github.com/FurinyaWorks/Slay-the-Heavens/blob/55d6396c/docs/evidence/release-resource-20261122/README.md)

## Owner 最小回执

1. 提供或本地读回 v2.1.0 原始有声 `.gil`，核对上方发布 SHA-256；用批准 Production 底图生成同一最终 v2.1.1 `audio/candidate.json` 和 `.gil`。两份分别记录 sourceCommit、buildId、最终文件 SHA-256、payloadDigest、客户端版本和时间。确保文件及工作流采用相同候选身份。
2. 在 PC 沙箱两端各保存三组脱敏证据。① 关卡和服务器存档数值及显示限值、配置人数、配置档位和平台作品详情最终档位。② 静态全局及全部区域，展开告警。③ 开启动态检测，完成首次战斗、十张手牌、多敌/特效并发、卡组和切页、循环退出重进、官方试玩校验后退出，附四类官方原始动态报告及失败提示。依据同构建收据执行 `npm run verify:platform-load -- <audio/candidate.json> <official-load.json>`。
3. 线上 v2.1.0 与同配置候选分别在一台受影响手机和 iPhone 14 Pro 各录一次冷、一次暖的 T0–T3。相同画质、帧率目标、网络、账号资格和同场景手牌输入；每轮记录设备、客户端、温度/低电量模式、网络、缓存状态、时间点、入口提示或原文错误码。能复现时增加配对轮次，保留超时样本。客户端未启动 Lua 时保留 T0 录像和平台反馈。正式发布仍由 Owner 人工执行。
