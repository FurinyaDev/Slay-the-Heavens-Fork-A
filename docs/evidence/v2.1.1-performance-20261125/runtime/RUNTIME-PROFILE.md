# v2.1.1 离线运行时剖析

这份报告比较线上 v2.1.0 `eb64f4e6cd45198118e123b6640dc491f186e329` 与从该版本建立的 Hotfix `f10eefa27c75788cf0b753d5e9121e3887114218`。实验执行实际 Lua `OnStart`、`OnUpdate`、战斗规则和 UI 投影，原生调用通过仓库的契约替身。官方客户端下载、资源调度、LuaHost 内部、GPU、GC 停顿、设备温控以及同产物的实机表现均待验。

## 发现

- **启动同步查找缩减已重现。** 两侧都构建 24,128 个替身控件，冷启动阶段 `GetChild` 从 5,119 降到 4,733，少 386 次（7.5%）。同段其他计数保持一致，符合 [#954](https://github.com/FurinyaWorks/Slay-the-Heavens/pull/954) 复用地图分组查找的改动。离线无计数版启动阶段 CPU P50 从 193.1 降到 107.7 ms。阶段包括替身克隆，且共享 CPU 压力影响绝对耗时。独立的模块加载阶段 P50 为 197.1→208.6 ms。
- **战斗的 SDK 改动范围有限且明确。** 120 次空闲更新中 `SetVisible` 347→227，共少 120 次，对应敌名的可见性守卫。十张手牌 60 次更新少 61 次 `SetVisible`，三次出牌阶段少 87 次。暖开卡组的计数完全一致，两侧都是 4,354 次计数 SDK 调用、3,350 次替身字段写入、零新增控件。实机 SDK 每次操作成本未知。
- **首战长更新和连续出牌有不同的热点。** Hotfix 首战合计 CPU P50 31.8 ms，其中样本内最慢一次更新的 P50 是 29.5 ms，观察最大 45.6 ms。其 1,500 个 Lua 指令栈样本中，55.5% 经过 `abyss_game_ui_view.lua:608` 的页面刷新，53.1% 经过 `abyss_battle_render.lua:15`。三次出牌中 `abyss_snapshot.lua:7` 占 1,390/5,057 个栈顶样本（27.5%），战斗 `render` 出现在 2,476 个样本（49.0%）。峰值提示应追踪投影和快照路径，保留快照的回滚语义及战斗反馈顺序。
- **十张手牌的 Lua 热点是姿态几何。** Hotfix 的 `abyss_battle_card_view.lua:63` 几何计算占 147/1,221 个栈顶样本（12.0%）。十张手牌阶段不增加替身控件。初次打开 75 张卡组只绘当前页，创建 10 个卡面根与 50 个分段，共 3,160 个替身控件。暖开、翻页及重复开关复用同一批根。测量的翻页阶段含关闭和战斗底页恢复，因而采到战斗重绘。
- **内存证据分开解释。** 计数模式的 Hotfix 冷启动 Lua 堆和进程 RSS 采样峰值中位数分别为 102.1 MiB 和 115.1 MiB，线上对照分别为 109.5 MiB 和 123.7 MiB。两侧卡组关闭循环阶段的 Lua 堆峰值中位数为 162.0→154.9 MiB，RSS 为 182.4→174.2 MiB。替身表、元表计数器、LuaTeX 及 Linux 进程库均计入。在 5 个线上计数进程中的 2 个观察到 Lua 堆净下降，Hotfix 计数时序中没有采到净下降。采样只证明区间堆净变化，实际 GC 次数和 GC 耗时待验。`OnDestroy` 验证更新停用，替身保留了整棵由引擎持有的控件树，实际场景卸载待官方客户端验证。

## 战斗与卡组交叉实验

以同一 Hotfix 为基线，独立替换早期 `85f5c50b9b610f639e4d582507033206013bfc18` 的手牌几何快路径，以及 [#932](https://github.com/FurinyaWorks/Slay-the-Heavens/pull/932) 的渐进卡组显现。敌名优化在四臂均开启。24/24 个进程完成，每臂 6 个交错配对区组，均在首战内打开 75 张卡组。各臂首次创建 10 个根和 50 个分段，暖开一律零新增。

| 改动 | 首张完整卡轮数 P50 | 全页就绪轮数 P50 | 首张卡 CPU P50 | 全页 CPU P50 | 暖开全页 CPU P50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Hotfix | 5.5 | 5.5 | 25.70 | 25.70 | 5.30 |
| 手牌几何快路径 | 4.5 | 4.5 | 17.26 | 17.27 | 5.35 |
| 渐进卡组 | 2 | 7 | 7.40 | 30.18 | 6.41 |
| 两项 | 2 | 6 | 7.33 | 22.57 | 5.16 |

以区组配对，手牌快路径对暖开 CPU 的中位差在无渐进时为 +0.61 ms，在有渐进时为 −0.73 ms，方向反转。对翻页及关闭的中位差分别为 −0.29 和 −1.93 ms。当前夹具未复现由战斗优化引发的一致卡组退化。不能由 6 个区组确认不存在小幅退化，也不能替代移动设备测量。对于复合状态保持 Hotfix 已择取的敌名优化，手牌快路径继续隔离。

## #932 回带界限

原 PR 精确 HEAD `00dc14e0b263572a47ddb5e855167ceeb3190ee7`。生产补丁在 Hotfix 的 `abyss_game_ui.lua` 和 `abyss_page_reveal.lua` 有冲突。实验采用相同卡面准备和模板隐藏逻辑，基于 Hotfix 的已有 `pointerBlocked`、房间转场、重入所有权及失败恢复做最小适配。实验 `tests/deck-pages.test.mjs` 1/1 通过。未将此实验应用到 canonical 源码。

独立使用 #932 地图探针，在现有 Hotfix 与移植变体上另完成 24/24 次新 Host 测量。正常预算下，10 张牌首张完整卡的 P50 从 4 轮降到 2 轮、12.939 降到 5.528 ms CPU。全页从 4 轮到 6 轮、12.939 到 20.805 ms。75 张牌的首张完整卡从 5.5 轮到 2 轮，正常预算的全页 P50 从 5.5 到 5 轮，最大总 CPU 从 26.005 到 38.909 ms。以 2.1 ms 每次预算检查的合成时钟控制准备步数时，冷开黑罩 42→0 轮、首张卡 42→10 轮，全页均 42 轮。该时钟不增加 CPU 工作或模拟手机。一次 75 张场景连续 20 次开关的两侧均保持 3,892 个卡组节点、49 个监听、10 个卡面根，循环中无新增或销毁。

建议保全补丁和测量数据，使用同一候选的设备回归决定渐进方案是否进入紧急发布。设备逐次记录输入、壳层、首张完整卡、全页、可点击以及返回操作，另查快速关开、取消、失败恢复、翻页后旧输入、战斗覆盖层和源房间切换。当前数据支持首张卡提早，不能承诺全页更快。
