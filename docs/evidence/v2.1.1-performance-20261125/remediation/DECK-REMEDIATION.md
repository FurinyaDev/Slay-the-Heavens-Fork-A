# v2.1.1 卡组往返诊断与修复

Hotfix 的生产修复从 `6492e8dccbcf847a0eba7ad3995da50257032e08` 拆出，实验提交为 `581d066538e4aee1bbd5735eaecd4bf58ee9af1a` 与收窄范围的 `722555e56c23b4b89f00af2f5b91a268536afd8a`。后者保留官方浏览器中已证实的操作数缩减，恢复默认旧 Grid 的原有轨迹。两个提交可按顺序应用到 canonical Hotfix。最终整合 SHA 以主线登记为准。

## 压力异常复核

第一次 Hosted 线上对照的组合压力卡组往返 P50 为 392.4→461.8 ms（+17.7%），配对三组均偏慢。其默认生成夹具使用旧式 Grid，仅调用 `openDeck()` 和 `closeDeck()`，未等待官方分页浏览器完成卡面准备。这个阶段两侧 SDK 计数 2,225→2,223，替身属性写 4,670→4,668，无额外模块加载或快照。

最新 Hosted run `45528828838` 对照的两棵树 `55d0bf58`、`6492e8dc` 之间只有文档和许可证登记变更，原始报告确认工作负载、依赖和生成 Lua 指纹相同。六档 36 次测量全部完成，无触发信号。组合压力下三对仍全部偏慢，分别为 619.90→671.44、581.52→613.44、591.45→684.37 ms，P50 591.45→671.44 ms（+13.52%）。无配额档亦出现同方向的三对偏移。当前证据无法把 +17.7% 归因到某个项目源码改动。下载的压缩包 SHA-256 `9e619fc01396cd42059d3a51ccea783bf7b5019e7efad5328bc162e40f94531f` 与 Artifact `14983519087` 登记一致。 [Hosted run](https://github.com/FurinyaWorks/Slay-the-Heavens/actions/runs/45528828838)

本地使用相同固定 Docker 镜像，试图做五组真实 stress 复跑。十次均因受控环境 Docker cgroup driver `none` 回读到外层 4 核配额而失败，要求的 0.5 核约束未施加。保留原始失败记录。本地无内部限额的固定 Node/Fengari worker 另跑 25 次全部通过，控制分组为线上、原 Hotfix、单独撤掉地图组查找缓存、单独撤掉敌名守卫、较宽的中间修复。SDK 和字段写能精确复现，计时波动较大，详细见中间数据。

中间修复涉及旧 Grid 关闭路径：默认 worker 确认少 12 条隐藏文本写，但 5 个配对中 4 个的墙钟较慢，配对中位差 +16.85 ms。最终补丁把旧 Grid 路径恢复到原有调用顺序和调用量，继续削减官方浏览器的重复调用。未将中间版本数据混入最终验收。

## 最终代码与复测

三个新进程配对复核最终默认路径，原 Hotfix 和最终补丁均为 2,223 次 SDK、4,668 次属性写、零模块加载和快照。墙钟 P50 249.743→236.900 ms，配对差为 −27.296、+4.529、−12.843 ms。小样本仅作默认路径未见稳定退化的核验。

- `abyss_deck_ui.lua` 在生成的官方浏览器使用独立排序栏时直接跳过已隐藏的旧排序按钮。遇到意外可见的旧按钮仍执行既有隐藏流程。旧 Grid 的文字、选中标记、排序方向与生命周期保持原路径。
- `abyss_deck_browser.lua` 复用已处于可见状态的卡面命中区。新建或真正隐藏的命中区仍调用原生 setter，保留写失败检查、过期输入门禁和恢复。现有契约测试注入 setter 拒绝，验证拒绝的命中区无法互动，恢复后重新启用；两种反向变体各自命中预期失败。
- 真实 UI Host 渲染链、同一生成配置、同一 seed 42，7 组裸计时与 7 组计数全部完成。统计包括冷开、暖开、翻页及关闭。初次创建仍为 10 个卡面根、50 个分段，零新增的暖开与翻页继续复用；全页就绪轮数中位数冷开 4、暖开 2，前后相同。
